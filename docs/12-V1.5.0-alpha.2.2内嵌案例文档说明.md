# V1.5.0-alpha.2.2 内嵌案例文档说明

## 1. 任务定义

- 任务编号：`DEV-V1.5-A2.2-001`
- 版本：`V1.5.0-alpha.2.2`
- 功能分支：`agent/ux-inplace-case-document`
- 目标：用户选择案例后，在当前地图工作台内直接阅读统一格式的案例文档。

## 2. 用户交互

1. 用户从左侧目录或地图标记选择案例。
2. 地图定位到项目点位，中央打开案例文档。
3. 顶部栏、左侧目录和右侧筛选仍保留在当前工作台。
4. 用户可点击遮罩、关闭按钮或按 `Esc` 返回地图。
5. 用户选择另一个案例时，当前文档在同一位置替换。
6. URL 使用 `?case={slug}&view=document` 保存状态。
7. 移动端以内嵌全屏文档展示。
8. “沉浸阅读”在新标签页打开原 `/cases/[slug]` 阅读器。

## 3. 内容选择协议

普通阅读统一按以下优先级取数：

1. `contentModel.editorialSections`；
2. 旧版 `article.sections` 映射到七部分；
3. 既有基础字段兼容内容。

固定七部分为：

1. 项目概况；
2. 为什么建设；
3. 如何建设；
4. 核心场景与业务闭环；
5. 实施与运营；
6. 创新与实际成效；
7. 经验、边界与适用条件。

缺少可靠证据的部分保留位置并明确标注“待补充”，不得用未经核验的推断填充。

## 4. 展示规则

- 阅读正文使用中文宋体/思源宋体系统回退，界面控件使用中文黑体/无衬线系统回退。
- 桌面正文有效宽度约 720px，文档容器最大宽度 860px。
- 正文约 16.5px、行高 1.95；一级案例标题约 32–42px；部分标题约 27px。
- 文章连续纵向滚动，不设置强制满屏章节和翻页动画。
- 关键要点、场景业务链、已复核图片和来源说明与正文一体展示。
- 普通阅读不直接展示 claim ID、冲突详情、模型日志和原始搜索过程；这些信息保留在研读/管理视图。

## 5. 兼容边界

- 不修改 V1.4 地图数据、点位聚合和左右侧栏架构。
- 不删除独立案例阅读器。
- 不修改 AI 解析任务链、数据库或账号权限。
- 不实现新的翻页动画。

## 6. 验收标准

- 点击案例时页面路由不离开 `/` 或 `/workbench`。
- 文档打开后 URL 含 `view=document`，刷新后能恢复。
- 遮罩、关闭按钮与 `Esc` 均可关闭文档。
- 七部分顺序固定，原生内容模型优先于旧版文章。
- 场景字段按业务闭环展示，已复核图片按部分展示。
- 手机端文档全屏且正文可滚动。
- 类型检查、ESLint、单元测试、渲染测试和生产构建全部通过。
