# V1.5.0-alpha.5 批量迁移说明

## 阶段目标

将 V1.4 的 20 份内置案例全部迁移到统一七章内容协议，同时严格区分“完成数据结构迁移”和“完成内容生产”。

## 迁移结果

| 类型 | 数量 | 当前状态 |
|---|---:|---|
| 标杆案例 | 3 | 原生深度内容，进入人工终审 |
| 批量迁移案例 | 17 | 七章结构已建立，待扩写、补证据、补媒体和审核 |
| 合计 | 20 | 20/20 完成协议迁移 |

## 稳定性约束

迁移不会修改案例 ID、slug、发布状态和地图坐标，因此既有目录定位和分享链接保持兼容。每份案例新增：

- `batchId`：可追踪迁移批次；
- `reviewGates`：六项终审门槛；
- `reviewStatus`：人工复核状态；
- `sourceCount` 与 `substantiveSectionCount`：迁移质量观察字段。

## 真实性边界

17 份批量迁移案例的 `generationMode` 已统一为 `native`，但 `manualReviewStatus` 和迁移复核状态保持 `pending`。系统不会因为数据结构已经齐全，就把兼容生成的段落、未经核验的来源或缺失的图片冒充成正式标杆内容。

## 后续处理顺序

1. 按专题选择下一批重点案例。
2. 联网补充权威来源与正式项目名称。
3. 重写七章内容并建立陈述—来源关系。
4. 补充指标、数据资产、场景闭环和图片证据。
5. 由内容负责人逐项通过六项门槛。
6. 保存为同 ID 的审核版本，覆盖内置展示但保留原始基线。
