# 开发交接说明

## 1. 交付物性质

本工程是 DigitalX V1 的可运行源码，不是静态截图，也不是单个 HTML。请用 VS Code 打开整个工程文件夹。

当前代码适合：

- 继续迭代现有 V1；
- 评估 V2 数据库、权限、文件和 AI 服务工作量；
- 作为前后端接口和业务流程讨论基线；
- 保留现有 Sites 演示站并继续发布。

不应把它直接当作已经具备生产能力的成品系统。

## 2. 首次接手顺序

1. 阅读 `README.md`；
2. 阅读 `docs/01`、`02`、`03`；
3. 复制 `.env.example` 为 `.env.local`；
4. 执行 `npm ci`；
5. 执行 `npm run dev`；
6. 打开首页、管理端和任一案例详情；
7. 执行 `npm run typecheck` 和 `npm run lint`；
8. 在 Bash/WSL 环境执行完整构建与测试；
9. 再评估功能拆分和 V2 方案。

## 3. 不要误判的地方

- 管理端已通过 `/api/ai/parse-case` 接入 Gemini与OpenAI双模型路由；AI 只生成草稿，不直接发布；
- 管理端“联网研究并扩展长文”仅在 Gemini 模式下启用 Google Search grounding，会增加搜索与 Token 用量；
- `lib/location-resolution.ts` 负责省级案例的省会展示锚点兜底；它是地图定位规则，不是项目事实；
- 文件选择不会把文件上传到服务器；
- 发布状态保存在当前浏览器，不是数据库记录；
- 没有管理员登录和权限拦截；
- `db/` 和 Drizzle 是预留，不代表数据库已建；
- 内置案例是演示样例，不能作为完整业务数据；
- `.openai/hosting.json` 是现有 Sites 项目标识，不是密钥，不要随意重建或替换。

## 4. 环境与密钥

真实环境变量不得进入 Git：

- `AMAP_JS_KEY`
- `AMAP_SECURITY_CODE`

若要新增数据库、对象存储或 AI 服务，统一在 `.env.example` 增加变量名和用途说明，真实值配置在本地或部署平台。

## 5. 代码拆分建议

不要先推倒重写。建议在第一个真实闭环中逐步拆分：

### 首页

- `CaseFilters`
- `CaseList`
- `CityPanel`
- `HomeStats`
- `useCaseFilters`

### 管理端

- `SourceImportPanel`
- `ParseStatus`
- `CaseEditor`
- `QualityPanel`
- `PublishActions`
- `LocalCaseQueue`（之后替换为服务端队列）

### 阅读器

- `ReaderToolbar`
- `ReaderSidebar`
- `ReaderSettings`
- `PagedReader`
- `ResearchView`
- `useReaderPreference`

### 数据层

- `CaseRepository`：统一内置、本地和数据库读取接口；
- `CaseService`：发布、复核、版本和校验；
- `SourceService`：原始资料与文件；
- `ParseService`：提取、OCR 和大模型任务。

## 6. 接口设计前必须确认

- 谁可以创建、复核、发布、撤回和删除；
- 原文件是否必须永久追溯；
- 同一来源重复导入如何判断；
- AI 结果、人工修改和发布版本如何保留；
- 案例更新后旧版本是否可查看；
- 删除是软删除还是物理删除；
- 地图坐标由 AI、地理编码还是人工确认；
- 来源证据和专业判断如何分开存储；
- 真实部署在 Sites、其他托管平台还是公司服务器。

## 8. ZIP 内容说明

交付 ZIP 不包含：

- `node_modules/`
- `dist/`
- `.next/`
- `.sites-runtime/`
- `.wrangler/`
- `.git/`
- `.env.local`
- 任何真实密钥

解压后必须重新执行 `npm ci`。这是标准源码交付方式，不是缺文件。
