# V1.5.0-alpha.3 存量案例迁移说明

## 1. 阶段目标

V1.5.0-alpha.3 将“兼容旧案例”推进为“可追踪地迁移旧案例”。本阶段不改 V1.4 地图主架构，不改变案例稳定标识、地图坐标或公开链接，只升级内容层。

首批标杆样稿：

1. 广州 CIM 基础平台与工程建设协同应用；
2. 北京城市运行综合指挥与一网统管应用；
3. 杭州城市大脑交通治理应用。

## 2. 迁移状态

每个内置案例新增 `contentMigration` 元数据：

| 状态 | 含义 | 是否可视为终审完成 |
|---|---|---:|
| `legacy` | 仍使用 V1.4 简版字段和兼容展示 | 否 |
| `migrated` | 已转为 V1.5 七部分内容协议 | 否 |
| `benchmark_draft` | 已完成标杆样稿和来源整理，等待内容负责人终审 | 否 |
| `approved` | 已完成来源、表述、指标和媒体终审 | 是 |

`benchmark` 只是内容生产等级，不代表已经人工批准。公开界面必须显示“标杆样稿”而不是“权威认证”。

## 3. 不变性约束

迁移不得改变：

- `id`；
- `slug`；
- 公开状态；
- 省、市和地图坐标；
- 既有分享链接；
- V1.4 地图目录和筛选逻辑。

内容升级只允许更新摘要、主体信息、七部分正文、来源、事实主张、数据资产、业务场景、指标、时间线、限制条件和复制条件。

## 4. 标杆案例验收门槛

每个标杆样稿必须满足：

- 使用 `generationMode=native`；
- 七个固定章节均有实质内容；
- 至少 4 个公开可追溯来源；
- 每章至少有一个来源关联的事实主张；
- 至少 2 个完整业务场景；
- 至少 2 类数据资产；
- 至少 3 条限制条件和 3 条复制条件；
- 数字指标标明来源、时期和口径，不跨材料合并；
- 状态保持 `in_review`，直到内容负责人完成终审。

## 5. 来源与事实规则

优先使用政府部门、项目主管单位和国家级行业机构的公开材料。正文采用编辑性转述，不复制长段原文。

- 来源支持的事实标记为 `source_claim`；
- 数字指标标记为 `source_claimed`，并保留原始时期和范围；
- 缺少统一口径的效率、成本和覆盖率不得推断；
- 实施和运营单位无法从公开材料确定时，必须显示“待终审”；
- 算法、平台或大屏能力不得自动等同于治理成效。

## 6. 当前迁移结果

当前 20 个内置案例中：

- 3 个为 `benchmark_draft`；
- 17 个为 `legacy`；
- 0 个为 `approved`。

右侧工作台显示迁移覆盖率。案例 POI 卡和内嵌文档显示“标杆样稿”标识，避免用户把编辑样稿误解为人工终审版本。

## 7. 后续批量迁移

后续案例沿用同一流程：

1. 冻结案例身份和稳定链接；
2. 收集并审查来源；
3. 抽取事实、主体、数据、场景和指标；
4. 生成七部分正文；
5. 执行自动质量检查；
6. 编辑人员复核标题、事实、数字、图片和边界；
7. 将迁移状态改为 `approved`；
8. 保留迁移记录和版本差异。

批量迁移不得绕过人工终审，也不得以生成字数替代内容质量。
