# 系统架构与数据流

## 1. V1 当前架构

```text
浏览器
├── 公开首页
├── 管理工作台
├── 阅读器 / 研读模式
├── localStorage
└── 高德地图 JS API
        ↑
Next.js / Vinext 应用
├── 页面路由
├── DeepSeek 低成本基础解析
├── 千问联网研究
├── Gemini 扫描 PDF 后备识别
├── 高德配置接口
├── 高德安全代理
├── 内置案例数据
└── Cloudflare Worker 构建输出
```

V1 没有正式业务数据库。页面读取 `lib/mock-cases.ts`，再在客户端合并 `localStorage` 中的本地案例。

## 2. 主要代码职责

| 位置 | 职责 |
|---|---|
| `app/page.tsx` | 首页搜索、筛选、地图、城市和案例联动 |
| `app/admin/page.tsx` | 管理工作台和模拟生产流程 |
| `app/cases/[slug]/page.tsx` | 案例详情路由入口 |
| `components/case-detail-client.tsx` | 阅读器和研读模式 |
| `components/amap-case-map.tsx` | 高德地图加载、城市标记与聚合 |
| `lib/case-model.ts` | 案例类型、枚举和分类颜色 |
| `lib/mock-cases.ts` | 内置演示案例 |
| `lib/local-cases.ts` | 浏览器本地案例的增删改读 |
| `lib/case-analytics.ts` | 城市、分类和项目状态统计 |
| `app/api/amap/*` | 地图配置与安全代理 |
| `db/schema.ts` | 正式数据库预留，当前为空 |

## 3. 当前 AI 草稿与发布数据流

```text
管理端粘贴正文 / 选择 PDF
  → 文本 PDF 浏览器本地提取（可用时）
  → 服务端AI提供商路由（DeepSeek基础解析 / 千问联网研究）
  → 千问失败自动降级为DeepSeek
  → 扫描PDF使用Gemini后备识别（已配置时）
  → 严格 JSON Schema 结构化结果
  → 省级项目位置智能补全
  → 字段证据、置信度和待核验项
  → 用户修改 SmartCityCase
  → 保存到 localStorage
  → 触发 digitalx-cases-updated 事件
  → 首页重新合并本地与内置案例
  → 已发布案例进入检索、地图和详情
```

AI模型调用是真实服务端能力；草稿保存与发布仍只在同一浏览器中成立。PDF 原文件不会保存到云端，网页链接不会自动抓取。

## 4. 核心数据对象

当前核心实体为 `SmartCityCase`，包括：

- 标识：`id`、`slug`、`title`；
- 空间：省、市、区、经纬度、空间层级、位置置信度、定位方法与推断说明；
- 分类：类别、年份、覆盖类型、项目阶段；
- 建设：主体、实施单位、运营单位、投资与资金来源；
- 内容：摘要、痛点、方案、成效、标签、专业判断和联网案例研究；
- 联网证据：实际检索词、可验证来源链接；
- 证据：来源类型、来源说明、来源链接、来源标题、原文摘录、证据等级；
- 流程：草稿、待复核、已发布；
- 时间：导入时间、更新时间。

## 5. V2 目标架构

```text
用户端 / 管理端
       ↓
应用服务与权限
├── 案例服务
├── 发布审核服务
├── 文件服务
├── 解析任务服务
└── 搜索服务
       ↓
数据与存储
├── 关系数据库
├── 对象存储
├── 解析结果与任务日志
└── 搜索索引
       ↓
外部能力
├── PDF/网页文本提取
├── OCR
├── 大模型结构化
└── 高德地图
```

## 6. V2 推荐核心实体

| 实体 | 作用 |
|---|---|
| `users` | 用户身份和状态 |
| `roles` / `user_roles` | 管理员、编辑、复核、只读权限 |
| `sources` | 原始网页、PDF、图片和来源元数据 |
| `files` | 对象存储文件、哈希、大小、类型 |
| `parse_jobs` | 提取/OCR/大模型任务及错误状态 |
| `case_drafts` | 尚未发布的结构化草稿 |
| `cases` | 对外发布的稳定案例实体 |
| `case_versions` | 每次发布的不可变版本 |
| `reviews` | 复核人、意见、结果和时间 |
| `reading_progress` | 用户阅读位置与偏好 |
| `notes` / `favorites` | 后续个人研读能力 |

## 7. 状态建议

案例建议采用明确状态机：

```text
新建
→ 待解析
→ 解析中
→ 待编辑
→ 待复核
→ 退回修改 / 待发布
→ 已发布
→ 已归档
```

解析任务和案例发布状态应分开，避免解析失败直接污染正式案例。
