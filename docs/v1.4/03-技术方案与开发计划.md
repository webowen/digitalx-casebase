# DigitalX V1.4 技术方案与开发计划

## 第二阶段实现记录

- 地图组件新增城市聚合与精确案例点位双模式；
- 地图层级统一为全国、省域、城市、项目四级；
- 案例坐标按 `locationLevel` 选择缩放级别，并持续显示位置置信度；
- 工作台状态通过 URL 查询参数持久化，不引入新的路由状态依赖；
- 目录采用原生 `details` 与 DOM 定位，在选中案例变化时自动展开；
- 中央预览优先使用已纳入且已人工复核的媒体资产，避免未经确认的图片进入公开预览。

URL 参数约定：

| 参数 | 含义 |
|---|---|
| `q` | 搜索词 |
| `category` | 应用分类 |
| `year` | 案例年份 |
| `evidence` | 证据等级 |
| `province` / `city` | 地理筛选 |
| `case` | 当前案例 slug |
| `level` | 地图层级 |
| `directory` | 目录组织方式 |

## 1. 改造策略

采用渐进式替换：

```text
/                  V1.4 地图案例工作台（正式入口）
/workbench         V1.4 地图案例工作台（兼容入口）
/legacy            V1.3 经典首页归档
/cases/[slug]      继续复用现有阅读器
/admin             继续复用现有管理端
```

新工作台验收前不改变 `/`，不修改案例生产流程，不迁移生产数据。

## 2. 复用与新增

| 模块 | 方案 |
|---|---|
| `SmartCityCase` | 原样复用 |
| 内置案例和本地案例 | 原样复用并合并公开数据 |
| 高德地图加载器 | 复用，增加自适应高度参数 |
| 阅读器 | 原样复用 |
| 管理端与AI接口 | 原样复用 |
| 工作台页面 | 新增 |
| 多维目录 | 第一阶段在工作台页面内实现，稳定后拆组件 |
| 状态管理 | 第一阶段使用页面级 React state |
| URL状态 | 后续阶段实现 |

## 3. 状态设计

第一阶段保持一份筛选状态：

```text
publishedCases
  → keyword/category/year/evidence/city
  → filteredCases
  → cityStats
  → tree groups
  → selectedCase
```

地图、目录、统计和预览全部从 `filteredCases`派生，不分别维护结果副本。

## 4. 分阶段开发

### 阶段一：基础工作台

- 路由、桌面布局、移动抽屉；
- 多维目录基础树；
- 地图自适应容器；
- 案例预览；
- 基础筛选和统计；
- 自动测试。

### 阶段二：深度联动

- 精确案例点位；
- 目录自动展开和滚动定位；
- URL状态；
- 行政区与城市层级切换；
- 收藏和最近浏览。

### 阶段三：专业研究工具

- 案例对比；
- 图层控制；
- 专题案例集；
- AI自然语言检索；
- 统计与导出。

### 阶段四：生产化

- 正式数据库；
- 用户权限；
- 服务端筛选和分页；
- 性能、日志与监控；
- 将新工作台切换为正式首页。

## 5. 发布策略

- V1.3 稳定版本通过 Git 标签与 `/legacy` 保持可回滚；
- V1.4 完成独立功能分支验收后合并至 `main`；
- 每个阶段通过类型、规范、构建、自动测试和真实交互点测；
- 第一阶段只提交评审，不自动替换首页；
- 最终验收后合并 `main`并建立 `v1.4.0`稳定版本。
