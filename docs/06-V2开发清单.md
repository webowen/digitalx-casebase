# V2 开发清单

## 1. V2 总目标

把 V1 的“完整前端演示闭环”升级为“可供个人或小团队真实使用的数据闭环”。不以新增更多页面为首要目标。

## 2. 推荐实施顺序

### P0：建立工程基线

- GitHub 私有仓库；
- `main` 稳定分支；
- 功能分支与 Pull Request；
- TypeScript、Lint、构建和基础测试；
- 本地、测试、生产环境变量分离；
- CHANGELOG 与版本标签。

验收：任一新电脑可克隆、安装、启动和构建。

### P1：真实人工发布闭环

范围：

- 管理员身份；
- 正式案例表；
- 人工创建和编辑；
- 保存草稿；
- 提交复核；
- 发布；
- 首页与阅读器读取数据库。

暂不包含 AI 解析。

验收：

1. 刷新后不丢数据；
2. 手机和电脑读取同一案例；
3. 未授权用户不能进入写操作；
4. 发布后首页可检索；
5. 撤回后前台不再展示；
6. 操作失败不产生半条数据；
7. 重要操作有日志和时间。

### P2：原始资料与文件

- PDF、图片和文档上传；
- 网页 URL 登记；
- 对象存储；
- 文件大小和类型限制；
- 哈希去重；
- 来源与案例关联；
- 下载、预览和删除规则。

验收：任何已发布案例都能追溯原始来源，权限和删除策略明确。

### P3：解析与 AI 结构化

- PDF 文本提取；
- 扫描件 OCR；
- 网页正文提取；
- 异步解析任务；
- 大模型结构化输出；
- 字段置信度与缺失项；
- 人工逐字段复核；
- 原文引用定位；
- 失败重试、超时和成本记录。

验收：AI 只生成草稿，不能绕过人工复核直接发布。

### P4：版本、审核与数据治理

- 发布版本；
- 修改前后差异；
- 退回意见；
- 软删除和归档；
- 来源失效检查；
- 证据等级规则；
- 数据导出、备份和恢复。

### P5：个人研读能力

- 跨设备阅读进度；
- 收藏；
- 笔记和批注；
- 个人标签；
- 案例对比；
- 语义搜索或案例问答。

这些能力应在真实案例数据稳定后开发。

### P6：正式发布与运维

- 独立域名；
- HTTPS；
- 中国大陆部署时评估 ICP 备案；
- 日志、错误监控和性能监控；
- 数据库备份和恢复演练；
- 费用和调用量告警；
- 权限审计；
- 隐私、版权和来源合规说明。

## 3. 第一条开发任务建议

建议 V2 的第一条正式任务写成：

> 保持 V1 界面不变，接入管理员身份和正式案例数据库，完成“人工创建 → 草稿 → 复核 → 发布 → 首页检索 → 阅读器打开”的真实纵向闭环；暂不接文件上传和 AI 解析。

## 4. 暂不优先

- 继续堆叠驾驶舱；
- 为展示新增大量假统计；
- 一开始就做复杂推荐算法；
- 同时接入多家大模型；
- 未明确权限和数据结构前做 AI 自动发布；
- 为了“正式”过早自建复杂服务器。

## 5. 里程碑

| 里程碑 | 结果 |
|---|---|
| V1.0 Prototype | 高保真前端原型与线上演示 |
| V1.1 Engineering Baseline | 源码交接、Git、文档、测试 |
| V2.0 Data Loop | 账号、数据库、人工发布闭环 |
| V2.1 Source Pipeline | 文件、网页、解析任务 |
| V2.2 AI Assisted | AI 结构化与人工复核 |
| V2.3 Knowledge Workspace | 收藏、笔记、对比、语义检索 |
| V3 Production | 正式用户、运维、合规和规模化 |
