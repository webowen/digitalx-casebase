# V1.5.0-beta.3 标杆案例自动生产链

本阶段目标不是新增复杂编辑器，也不是重做前台阅读界面，而是把案例库的核心能力收敛到一件事：

> 输入一个项目名称、PDF、网页正文或粘贴材料，系统自动生成接近正式案例报告质量的结构化案例草稿。

## 1. 适用输入

- 项目名称：例如“大湾区文化体育中心智慧运营管理平台”；
- PDF：优先提取文字和高信息密度页面，扫描件仍依赖视觉模型；
- 网页链接 + 正文：链接用于来源记录和图片候选，正文仍由用户粘贴；
- 粘贴原文：适合新闻稿、公众号正文、招标公告和项目介绍。

## 2. 标杆模式与普通模式

| 模式 | 适用场景 | 搜索与写作策略 |
|---|---|---|
| 普通解析 | 日常入库、低成本草稿 | 默认最多2组联网检索，生成七章结构化草稿 |
| 标杆报告模式 | 重点案例、正式展示、公众号或报告素材 | 最多4组重点检索，提高正文长度、证据密度和质量评分门槛 |

标杆模式允许“仅输入项目名称”作为合法输入。系统不会因为原始资料较短而直接拒绝，而是先生成项目身份候选，再通过联网研究补全。

## 3. 任务链

1. 输入校验：识别项目名称、PDF、正文或网页资料；
2. 原始资料提取：本地提取 PDF 文本和图片候选；
3. 项目身份核验：判断正式项目名称、地区、类型、主体和位置置信度；
4. 联网资料研究：围绕正式名称、建设单位、实施单位、获奖、招标和平台能力检索；
5. 事实与证据抽取：形成 claims、主体、数据资源、业务场景、指标、里程碑和限制条件；
6. 规范化内容生成：按七章结构生成长篇案例报告草稿；
7. 质量规则检查：标杆模式目标评分不低于78分；
8. 等待确认：AI 输出为待确认草稿，重点核验高风险事实、图片授权和发布边界。

## 4. 七章报告结构

1. 项目概况；
2. 为什么建设；
3. 如何建设；
4. 核心场景与业务闭环；
5. 实施与运营；
6. 创新与实际成效；
7. 经验、边界与适用条件。

标杆模式下，系统会要求每章形成连续可读正文，并在最后一章加入 Digital X 案例评审视角：为什么值得入库、哪些内容不能夸大、复制推广需要哪些条件。

## 5. 图片处理原则

- PDF 中提取的高信息密度页面会作为图片候选进入 AI 编排；
- AI 优先匹配平台界面、大屏、架构图、流程图、地图和现场图；
- 没有图片时，正文不会伪造图片，只会提示建议补充的图片类型；
- 图片仍标记为待确认，发布前需要确认来源和授权。

## 6. 黄金样例

管理端新增“大湾区文体中心黄金样例”按钮，用于快速测试标杆生产链。

验收关注点：

- 仅输入项目名称也能进入任务链；
- 标题应保持为具体项目名称，而不是文件名或宣传标题；
- 联网检索组数在标杆模式下可增加到4组；
- 生成结果应为固定七章、长文报告化表达；
- 系统能够把图片候选绑定到章节，或提出补图建议；
- 质量结果能区分事实、推断、待核验和发布边界。
